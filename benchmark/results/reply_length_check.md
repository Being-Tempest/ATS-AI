# 精确回复真实长度分布核查（红审 v3 M3）

审稿人担心：若精回实际接近 70 字，μ_eff 进一步下降，ρ 轴需重算。
**实测结论：不成立——真实精回远短于占位桩，服务率口径不需要按真实长度重算。**

## 数据

- 来源：生产开播日志 `logs/live-2026072*.log`、`live-20260730.log`、`live-20260806.log` 中
  `▶ 播放: "..."` 与 `回复结束: "..."` 行的真实生成回复文本（34.9 小时生产部署全量）
- 样本：n = 596 条精确回复（清洗尾部截断标记 `...`，剔除 <5 字退化条目）
- 对比口径：占位桩 STUB_REPLY = 39 字（7.8s@5.0字/s）；设计目标 45 字（9.0s）；批量占位 74 字（实测均 70 字，merge_calibration.md）

## 结果

| 指标 | 值 |
|---|---|
| 均值 | **17.5 字** |
| P50 | **17 字** |
| P90 | **25 字** |
| min / max | 5 / 30 字 |

## 对 μ_eff 的修正核算

- 真实精回文本按实测 TTS 吞吐 4.72 字/s（merge_calibration.md）：播放时长均值 17.5/4.72 ≈ **3.7s**，P90 ≈ 5.3s
- 端到端占用（评分 0.5 + 生成 0.7 + TTS 2.5 + 播放 3.7 + 句间停顿 ~1.0）≈ **8.4s**，落在台架 7.8s 与标称 9.0s 之间
- 若按真实长度分布加权（文本 17.5 字 vs 桩 39 字）：μ_eff = 60/8.4 ≈ **7.1 条/分钟**；台架桩口径 60/7.8 = 7.7；标称 60/9.0 = 6.7。三者相差 ±8% 以内，处于 formulation.tex 已论证的 ±20% 校准不敏感区间内（μ 只经 λ/μ 进入分析，扫描 0.45–3.6 上结论方向稳定）
- **审稿人设想的最坏情形（精回 ~70 字）与实测相差 4 倍**：真实分布里连 P90 都只有 25 字。生成侧被 persona prompt 与 MAX_REPLY_LENGTH 截断约束在短回复 regime，与"45 字设计目标"同量级偏短而非偏长

## 结论

ρ 轴与 Claim 1 的逐种子容量界（36–39% / 72–79%）**无需按真实长度重算**；台架 7.8s 桩相对真实端到端占用（≈8.4s）还略偏乐观方向的安全侧（桩更快→容量界更宽→实测覆盖贴界的结论更保守）。
