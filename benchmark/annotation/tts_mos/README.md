# TTS 语音质量 MOS 标注说明（盲听版）

> 目的：测量 AI 主播语音合成（TTS）的实际听感质量。你打的分会用于论文里的
> 语音质量披露。你的真实听感就是答案，没有对错。
> 标注对象：本目录下 18 个音频文件 `M01.wav`–`M18.wav`（已打乱顺序）。

## 任务

用耳机按顺序听每个 wav（每个 5-22 秒），在 `tts_mos_blind18.csv` 里给三个维度各打
1-5 分。这是一个虚拟主播在回应直播间弹幕的录音。

## 评分锚点

**自然度**（声音像不像真人说话）：

| 分 | 含义 |
|---|---|
| 5 | 几乎听不出是合成，语气起伏自然 |
| 3 | 明显是合成音，但语气不别扭 |
| 1 | 机械感重、语气怪异或出戏 |

**可懂度**（听不听得清内容）：

| 分 | 含义 |
|---|---|
| 5 | 每个字都清楚，不用回听 |
| 3 | 大意能懂，个别词需要猜 |
| 1 | 多处听不清在说什么 |

**疲劳感**（想象直播里连续听这种声音一小时）：

| 分 | 含义 |
|---|---|
| 5 | 完全不累，可以一直听 |
| 3 | 听久了有点累，尤其是长段 |
| 1 | 听几句就想关掉 |

## 注意事项

1. 每个文件**完整听完再打分**，长文件（十几秒的）请特别注意"疲劳感"维度。
2. 三个维度独立打：声音很自然但内容听不清、或很清楚但听久了累，都是可能的组合。
3. 打分只凭听感，不要看 wav 文件名以外的任何信息。
4. 全部 18 条预计 **15 分钟**左右。标完把 CSV 发回，"备注"列可留空。

## 回收格式（作者用，同学可忽略）

- 每位标注者返回一份 CSV，文件名改名为 `tts_mos_blind18_<姓名拼音>.csv`。
- 汇总：按编号对齐，分维度报全体均值 ± SD（MOS），并按隐藏 key `.tts_mos_key.json`
  的 `cls` 字段（short_precise / long_batch / emotion）分组报告，重点看 long_batch
  组的疲劳感是否显著更高。key 文件在汇总前不要打开、不要发给同学。
